# MachineSignal - Riepilogo Per Commercialista / Legale / Privacy

Data: 2026-06-17
Stato: riepilogo informativo, nessuna attivazione commerciale

## Perche' Questo Documento

Questo documento serve a spiegare in modo semplice il progetto MachineSignal a un consulente fiscale, legale o privacy.

Non e' una richiesta di attivazione commerciale.

Non stiamo ancora incassando, fatturando, raccogliendo metodi di pagamento, usando dati reali/personali o contattando clienti.

## Cos'e' MachineSignal

MachineSignal e' un progetto software/API.

L'idea e' vendere servizi digitali soprattutto a sistemi automatici, non a persone che leggono pagine commerciali tradizionali.

I potenziali utilizzatori sono:

- CRM;
- agenti AI;
- workflow automatici;
- strumenti RevOps/sales automation;
- software interni aziendali;
- altri sistemi che consumano API.

In pratica, una macchina cliente puo' chiamare la nostra API e chiedere:

- trova target aziendali coerenti con una richiesta;
- valuta una lista di domini o aziende;
- assegna uno score di opportunita';
- prepara un approfondimento strutturato;
- suggerisci l'azione successiva in formato leggibile da software.

## Cosa Potremmo Vendere In Futuro

I prodotti ipotizzati sono:

- pacchetti di target discovery;
- pacchetti di score;
- arricchimento domini/aziende;
- deep analysis;
- action pack;
- feed ricorrenti;
- abbonamenti API.

Al momento questi prodotti sono solo oggetto di test, documentazione e simulazione.

## Stato Attuale

Il progetto e' in fase sandbox/test.

Sono stati preparati:

- sito e documentazione pubblica;
- endpoint API di test;
- OpenAPI/Postman;
- regole di consumo crediti in sandbox;

## Cosa Non E' Attivo

Non sono attivi:

- pagamenti reali;
- fatture;
- raccolta metodi di pagamento;
- API key di produzione;
- uso di liste clienti reali;
- trattamento di dati personali;
- campagne email;
- contatti commerciali esterni;
- pubblicazione su marketplace/API directory;
- hosted MCP pubblico;
- MCP registry pubblico.

## Cosa Vogliamo Capire Dal Commercialista

Vogliamo capire:

- se e quando serve P.IVA;
- se e' possibile fare una beta gratuita senza P.IVA;
- se una beta a pagamento richiede subito P.IVA o altra struttura;
- come si fatturano crediti, pacchetti API e abbonamenti;
- come gestire IVA italiana, UE ed extra UE;
- come gestire rimborsi o riaccredito crediti;
- come registrare costi di AI, API, cloud e software;
- cosa serve prima del primo incasso reale.

## Cosa Vogliamo Capire Dal Legale / Privacy

Vogliamo capire:

- quali termini servono per una beta API/software;
- come limitare responsabilita' su score e raccomandazioni;
- come dichiarare che lo score e' supporto decisionale, non garanzia;
- se possiamo lavorare solo su dati aziendali pubblici;
- come bloccare o rifiutare dati personali;
- se serve una privacy policy anche per uso API machine-to-machine;
- se serve una DPA per clienti business;
- quanto possiamo conservare log, richieste e output;
- come gestire API key, incidenti e revoche;
- quali limiti esistono per eventuale comunicazione commerciale.

## Modello Di Rischio Che Vogliamo Tenere Basso

La beta, se in futuro venisse autorizzata, dovrebbe partire in modo molto controllato:

- pochi clienti;
- approvazione manuale;
- limiti bassi;
- nessun dato personale;
- nessun outreach automatico;
- produzione API key manuale;
- kill switch attivo;
- budget/cost cap;
- regole chiare su output validi e crediti.

## Decisione Corrente
